# 情境词卡（Context WordCards）

一个支持 Android 和 Windows 桌面的英语词汇学习应用。用户批量导入单词后，AI 从整批词汇的整体关系出发，自动决定场景数量、名称和分类边界，并为新词寻找合适的熟悉旧词作为联想。

单词、复习进度、场景分类、人工调整和词语关联均保存在本地。已有分类不会自动重新调用 AI，只有用户点击“重新分类”才会更新。

## 主要功能

- 粘贴多个单词，每行一个
- 粘贴 `word: 释义`、制表符、等号、逗号等常见格式
- 导入 CSV 前两列
- 导入预览：显示有效项、已有词、本批重复、空行和格式错误
- AI 根据整批单词动态生成场景，不依赖预设分类列表
- 场景页直接汇总全部场景，不再按导入批次分层；每个场景默认收起
- 可为每个场景生成并缓存 AI 总结：整体情境、词间联系、区别对比和记忆路线
- 大批量导入每 30 个词分组请求，已完成分组可断点续传
- 每组都会携带已有场景名称，由 AI 决定沿用已有场景或创建新场景
- 每次分类接口的原始返回按批次保存，可在应用内查看调试
- 一个单词可以属于多个真正相关的场景
- 显示分类理由、无法判断项和多场景项
- 分类确认前后均可重命名、移动、合并和拆分场景
- 从熟悉的旧词中生成自然联想、理由及双词例句
- 学习页只有一个“开始学习”入口，下面用紧凑单词按钮自由查看词卡
- 点“熟悉了，学习下一个”会加入记忆曲线并自动跳到下一个词
- 到期词每日乱序抽取，间隔为 1、2、4、7、15、30、60、120 天
- 开放式回忆：用户解释词义并造句，由 AI 自动评判和安排下次复习
- AI 提供具体反馈、清晰中文解释和示范回答，并保存评判记录
- 词卡和复习页支持多轮 AI 互动检查，从不同角度追问并判断是否真正记住
- AI 纠错会指出原句的具体问题、解释相关语法规则及错误原因，并沿着用户原意给出自然改写
- Android 返回键和系统边缘返回手势会返回学习列表或上一层页面
- 复习必须先手工输入开放式答案，AI 评判完成后才显示讲解
- 分类和关联持久保存
- API 密钥验证后安全保存，只需输入一次
- 多套 OpenAI 兼容 API 配置
- 兼容旧版 `words` 表和原有学习记录

## 单词本管理（0.7.0）

Android 和 Windows 均支持创建多个单词本，例如“建筑英语300词”“The Giver 生词”“日常工作”。单词本由用户按来源或目标整理，AI 场景分类继续独立保留。

- 应用打开默认进入单词本，可切换“全部单词”或某个本子。
- 支持新建、重命名、上移、下移和删除；默认单词本保留固定名称且不能删除。
- 旧词库首次升级时自动收录进默认单词本，词卡和复习进度不变。
- 一个词可收录进多个本子，词卡、学习状态和复习日期共用，不会重复排期。
- 每本显示总词数、未学数和到期数。搜索支持单词、释义和场景。
- “学习当前筛选”只在当前本子及搜索结果内推进；按本复习只抽取本内到期词，底部“复习”仍可复习全部单词。
- Android 点击“批量整理单词”后勾选；Windows 使用 Ctrl / Shift 多选。支持加入其他本子、从当前本子移除。
- 移除收录关系或删除本子会保留单词和复习记录；失去全部归属的词自动移入默认单词本。默认本中没有其他归属的词会继续保留。
- 导入前选择目标本子。已有词直接加入该本子，不重新生成词卡；只有新词调用 AI。未完成批次保存目标本子，重开后继续仍使用原目标；目标本子被删除时转入默认本。

## 完整备份与恢复

两端使用同一版本化 JSON 格式，包含词卡和学习进度、单词本与收录关系、导入批次及分组缓存、场景及人工调整、新旧词关联、复习评判、场景总结、AI 互动记录及已脱敏调试返回。不包含 API 配置和密钥。

- **完整备份恢复会替换当前词库**。恢复前先导出当前备份；页面会明确提示替换并要求确认。
- 备份先在临时数据库校验，确认格式、词卡、进度和核心关联完整后才写入；写入失败会回滚。
- 旧版单词数组 JSON 仍可合并导入，同名单词保留当前内容和复习进度。
- Android 可在单词本页或导入页操作；Windows 在单词本页操作。AI 请求进行中暂不允许备份或恢复。

## Android 安装

在仓库右侧的 **Releases** 中下载最新版 APK，在 Android 手机上点击安装。最低支持 Android 8.0（API 26）。

升级版沿用旧版应用 ID，以便覆盖安装并继续访问原有的私有 SQLite 数据。应用显示名称、文案、图标含义和业务流程均已改为通用的“情境词卡”。

## Windows 桌面版

需要 Python 3，并且系统自带 Tkinter：

```powershell
python desktop/app.py
```

也可以双击 `desktop/start_desktop.cmd`。在这个已有工作区中，桌面版会优先迁移原 `outputs/words.db`；新克隆的项目默认使用 `desktop/context_words.db`。

## 批量导入流程

1. 粘贴单词文本，或选择 CSV 文件。
2. 查看预览；已有单词收录进目标本子且不重新生成，本批重复项自动跳过，空行忽略，格式问题单独列出。
3. 确认有效列表及目标单词本，不需要创建或选择场景。
4. AI 对整批单词生成词卡、动态场景、分类理由、无法判断项和旧词关联。
5. 在分类预览中重命名、移动、合并或拆分。
6. 确认分类。结果和人工调整立即保存在本地。

AI 返回的草稿也会保存。超过 30 个词时会拆为多组逐次获取，每个已完成分组单独缓存；应用重开或请求失败后可以从未完成分组继续，不会重复支付已完成分组。后续分组会收到已确认场景和本批前面分组创建的场景名称，AI 可以沿用适合的名称，也可以创建新的具体场景。

## 场景聚类规则

提示词要求 AI：

- 从整批词汇的整体语义关系决定场景
- 场景名称简短、自然、具体
- 避免为每个单词单独创建场景
- 合并含义重复的场景
- 允许真正合理的多场景归属
- 对无法准确判断的词明确列出
- 为每个归属提供一句分类理由

应用会验证 AI 返回的词是否都来自当前批次、每个词是否有唯一词卡、场景数量是否合理、场景成员是否有效，以及关联旧词是否确实存在于用户词库中。当前整批导入的词会从旧词候选中排除；AI 偶尔返回的批次内、已删除或无理由关联会单独忽略，不再阻断有效的词卡和场景。其他结构错误仍不会覆盖已有结果。

每次分类请求的原始响应、分组编号、接收时间和本地校验结果会保存到本地。导入页或分类预览中的“查看 AI 调试返回”可以直接查看完整内容，便于判断是服务商报错、JSON 格式错误还是本地校验失败。记录不包含请求负载或 API Key。

## 新旧词联想

旧词统一使用“熟悉”状态。AI 获取旧词时优先选择熟悉且复习阶段较高的词；旧版本中的“已掌握”会自动迁移为“熟悉”，复习阶段和日期保持不变。

关联依据包括相关场景、近反义、常见共现、自然短语、上下位关系，以及确实有助于记忆的发音或拼写关系。每条关联包含类型、中文理由和同时使用新旧两个单词的英文例句。找不到合理联系时允许没有关联。

## 数据结构与迁移

原有 `words(word, content, stage, due)` 数据完整保留。启动时只做增量迁移：

| 表 | 用途 |
| --- | --- |
| `words` | 原词卡和共享复习进度；包含 `mastery`、`created_batch`、`learned_at` |
| `notebooks` / `notebook_words` | 用户自建单词本、排序和多对多收录关系 |
| `import_batches` | 导入批次及 parsed / draft / confirmed 状态 |
| `import_items` | 批次中的规范化单词和用户提供的释义 |
| `scenes` | AI 动态生成或用户调整后的场景 |
| `scene_words` | 多对多场景成员和分类理由 |
| `unclassified` | 无法准确判断的单词及理由 |
| `word_links` | 新词与旧词的关联、理由和例句 |
| `classification_chunks` | 大批量分类的分组结果及断点续传缓存 |
| `api_debug_responses` | 每次分类接口的原始返回和本地校验状态 |
| `review_attempts` | 开放式回答、AI 评判、讲解和脱敏原始响应 |
| `scene_summaries` | 按场景与成员指纹缓存的 AI 联系、区别和记忆路线 |
| `memory_chat` | 单词多轮互动问题、回答、分数、反馈和脱敏响应 |
| `api_profiles` | 桌面端 API 地址、模型及协议，不包含密钥 |

迁移不会删除旧词、复习日期或阶段。

新导入的词默认标记为“未学习”，不会因为导入日期是今天而立刻进入复习。用户阅读词卡后点击“熟悉了，学习下一个”，会自动加入记忆曲线，第一次复习安排在次日。旧数据中已有复习阶段或熟悉标记的词会自动迁移为已开始学习，其余词保留为未学习。

“全部场景”会把不同导入批次中名称相同的场景合并显示。展开场景后可按需生成 AI 总结；总结会和当前成员列表的指纹一起保存，成员未变化时直接读取缓存。词卡中的“和 AI 互动检查记忆”会保留最近对话，由 AI 逐轮改变提问角度，并给出 0–100 分和是否已经记住的判断。

## API 设置与密钥

每套配置包括名称、HTTPS Base URL、模型名称、接口格式和 API Key。支持 Responses 与 Chat Completions 的 OpenAI 兼容非流式接口。

- Android 使用 Android Keystore 生成设备内 AES-GCM 密钥，加密后保存 API Key。
- Windows 使用当前 Windows 用户的 DPAPI 加密密钥。
- 页面、日志和错误信息不显示完整密钥。
- 当前个人调试版本允许在 API 设置页截图；API Key 输入框仍使用密码遮罩。
- 修改密钥时重新验证；清除密钥不会影响单词、分类或关联。
- 地址、模型和协议可以保存；词库备份不包含 API 密钥。

首次保存或修改密钥时，应用发送一个很小的验证请求。验证成功后才保存。密钥失效时请求会提示重新设置。

某些推理模型会把很短的验证请求标记为 `incomplete`，因为输出额度先被推理过程用完。只要服务端已成功鉴权并返回合法 Responses 对象，应用会将其视为连接和密钥验证成功；正式分类仍要求完整结果。

对 `https://api.deepseek.com`，应用会自动使用 DeepSeek 当前支持的结构化输出参数并关闭分类请求中的思考模式；选择 Chat Completions 时自动改用 DeepSeek 的 JSON Object 格式。HTTP 错误会显示服务商返回的简短原因，但不会显示 API Key。

Android 手机直接连接所填写的 API，不会经过电脑。电脑正在使用的系统代理不会自动共享给手机；服务商需要代理或 VPN 时，必须在手机端启用。应用会分别提示域名解析失败、HTTPS 证书失败、连接被拒绝和请求超时，便于定位网络问题。

## Android 构建

仓库包含 Android Studio Gradle 配置，也提供已验证的独立构建脚本。需要 Python 3、JDK、Android Build Tools 35 和 Android Platform 35：

```powershell
python build_apk.py `
  --java "JDK目录" `
  --tools "Android Build Tools目录" `
  --platform "Android Platform目录" `
  --work "临时构建目录" `
  --out "context-wordcards.apk"
```

脚本完成 Java 编译、DEX 转换、资源打包、ZIP 对齐和 APK 签名。`--work` 中的签名文件必须保存，后续版本才能覆盖安装。

## 安全与兼容范围

应用当前支持 HTTPS + Bearer API Key，以及 OpenAI 兼容的 Responses 或 Chat Completions JSON 返回。部分服务商使用专有认证或不支持 JSON Schema，需要针对该服务商单独适配。

不要把 API 密钥写入源码、提交记录或 Issue。面向多人公开分发前，仍建议增加服务端代理、账户限额和滥用保护。

结构化输出设计参考 [OpenAI 官方 Structured Outputs 文档](https://developers.openai.com/api/docs/guides/structured-outputs)。
